Why the booking needs a search ID

  
A customer can be planning two trips. If they book the first, a rule that looks only at their customer ID would cancel the second reminder too. This model matches both the customer and the search. Compare a booking for this search with a booking for a different search.

  
With two open searches, both reminders can qualify. For a live rollout, the client would need to choose which search takes priority and how long to wait between messages. Here the model returns the decisions without sending anything.
