SEP 2026 · Troubleshooting note

200 OK is not the outcome.

A successful request proves that one layer accepted something. It does not prove the customer experience worked.

The API accepted it. Did the customer qualify?

Suppose a search event lands successfully but the consent flag sits on a different profile. The API can return 200 and the customer may still be ineligible. I’d start with one known record and follow the ID from the request to the profile and into the journey.

Technical success is only useful when it survives the full chain from source to customer outcome.

I troubleshoot the chain, not the tool.

TraceExpected → actual
Source→Ingestion→Identity→Profile data
Profile data→Eligibility→Journey→Channel / outcome

I start with the expected business behaviour and one known user or record. Then I move layer by layer until expected and actual diverge. That keeps the investigation evidence-based and prevents a tool, platform or team from becoming the default suspect.

Identity is a common hidden failure.

A backend event can land successfully while contact information, attributes or consent live on a different profile. From the API's perspective, everything worked. From the customer's perspective, nothing did.

That is why I treat identity separately from data ownership. “Who is this customer?” and “which system owns this fact?” are different questions, and both need explicit answers.

What I want before calling a fix done.

Known source record or event is correct
Intended identifier reaches the expected profile
Required attributes / events exist with the right types and freshness
Consent and channel eligibility are correct
Journey / automation logic evaluates as intended
Negative case fails safely
Monitoring can detect the same failure class again
An owner knows what to do when it happens

Where I stop the investigation

Do not stop at “the API returned success,” “the file landed,” or “the campaign sent.” Those are checkpoints. The outcome is the intended customer behaviour, reached through a chain the team can observe and operate.
